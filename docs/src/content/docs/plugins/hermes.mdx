On Hermes Agent a companion is a profile of its own: its persona is the
profile's `SOUL.md`, and clanka's tools are the only toolset it has.

## Install the plugin

You need `hermes` on your `PATH`, and Linux on x86_64 or arm64 or macOS on
Apple Silicon.

```sh
curl -fsSL https://clanka.jfa.dev/install.sh | sh
```

The script:

- downloads the latest [release](https://github.com/jfalava/clanka/releases)
  and checks it against the release's `SHA256SUMS`, installing nothing when
  it does not match,
- installs the `clanka` CLI under `~/.local/bin` (`CLANKA_BIN_DIR` picks
  another directory),
- installs the plugin under `~/.hermes/plugins/clanka`,
- installs the soul-writer skill under `~/.agents/skills/clanka-soul-writer`,
  so any agent on the machine can write a soul the same way,
- runs [`clanka hermes refresh`](/cli/hermes/#refresh).

## Make a profile for a companion

```sh
clanka hermes profile nova ~/.config/clanka/souls/<id>.md
hermes -p nova chat
```

The profile is that companion and nothing else. Hermes's own memory, user
profile, coding brief and agent-style guidance are off, so each turn carries
the persona and the conversation instead of Hermes's whole toolbox. A photo
you send goes to the model as an image, so pick a model that takes images,
and memory records it as `*shows you a photo*`.

The root's own providers, model aliases and the keys they read are copied
into the profile, so `/model <alias>` works in its chat.

Run the command again after [changing the persona](/souls/traits/#changing-the-persona)
to refresh the profile's `SOUL.md`. A gateway that already serves the profile
re-reads its config on its own.

To give a companion another toolset on one platform, add it next to clanka.
`clanka hermes profile` keeps it on later runs:

```sh
hermes -p nova config set platform_toolsets.telegram '[clanka, image_gen]'
```

## Saying goodnight

The companion falls asleep when you say goodnight and its model calls
`go_to_sleep`. To be sure it does, start the message with `zz` or send
`/sleep`:

```text
/sleep night, see you tomorrow
```

`/sleep` sends `zz` and your words as your next message, and the companion
answers it before it sleeps; in a dream, it wakes. Hermes
lets a plugin send a message only with
`plugins.entries.clanka.allow_gateway_injection`, which
`clanka hermes profile` sets. On an older profile, run it again, or send `zz`
yourself.

## Triage

`/triage` answers with what clanka did lately for the companion: its state
now (in a conversation, dreaming, frozen or none open) and its last 15
[diagnostics events](/cli/diagnostics/), such as the markers a message used,
whether a `zz` ended a dream and how each pass over memory went. It holds only
counts and fixed words, never what was said or remembered, so it is safe in a
group chat and in a bug report. Hermes answers it without a turn: the
companion never reads it, and nothing is recorded. See
[`/triage`](/cli/chat/#triage) for an example.

## Lore

A companion whose `soul.md` grants [lore](/lore/reading/) reads it on
Hermes as everywhere: an entry you name opens on its own, and the model can
open one with its `read_lore` tool. `/lore` lists the entries, `/lore <id>`
shows one as the companion reads it, and `/lore strike <id> <line>` hides a
companion's line. Like `/triage`, none of them is a turn.

When the lore the companion reads has an error
[`clanka lore lint`](/cli/lore/#lint) reports, every turn is refused with a
`clanka:` notice. Fix the lore and send the message again; Hermes needs no
restart.

## When a conversation ends

The companion has one conversation at a time, and a goodnight ends it: the
next message starts a new one at once, while sleep, in the background,
writes the night's episode, settles its mood, lets the memories that came up
drift and raises what was left unresolved. Once it has slept, or woken from a
dream, clanka posts one line to the chat saying so, such as
`clanka: Awake. 2 fragments linger, 1 memories shifted.` The line holds only
counts, never anything said or remembered. Hermes doesn't keep it in the
conversation, so the companion never reads it. Hermes versions without
plugin messages, and chats that are already closed, get no line; it goes to
the Hermes log instead. On Hermes the companion falls asleep:

- On a goodnight, `zz` or `/sleep`.
- On `/new` or `/reset`. Hermes no longer ends a gateway chat after a quiet
  spell; the `hermes-session-reset-policy` plugin brings that back as a `/new`
  on your first message after the gap, and the companion sleeps on it too.
- When you leave the chat it is talking in from the CLI or the TUI: quitting,
  or a `hermes chat -q` one-shot exiting. Each one-shot is its own night, so a
  `--resume` after one starts a new conversation. A script that sends each
  message as a one-shot, like `hermes/bench.sh`, sets
  `plugins.entries.clanka.settings.sleep_on_leave` to `false`; leaving then
  keeps the companion awake, and a goodnight or `/new` ends the conversation.

It stays awake through:

- Another chat ending. One profile has one companion, so only the chat its
  last message came from counts.
- Ends Hermes makes on its own and keeps resumable: a dropped connection
  reaped, the gateway stopping or restarting, an idle or evicted session.
  The Desktop app ends a chat only this way, so there the companion sleeps on
  a goodnight or `/new`.
- Archiving or deleting a chat.
- The TUI or the Desktop app opening, resuming or reconnecting to a chat.
  Hermes reports each as a reset with no reason; before 0.3.2 the companion
  took it for a `/new`, which dropped a dream it was in.

### Why

A conversation left open runs into the next one. The companion's tiredness
counts every message of the open conversation, so it starts the next one
tired, it doesn't notice the time you were away, and nothing of the first is
slept on until the next goodnight.

Sleep can't be taken back, though, and Hermes ends chats it means to resume.
Sleeping on those would close a conversation halfway and write a night for
half of it. So only an end someone chose puts the companion to sleep, and
anything else leaves the conversation open for the next goodnight.

If a conversation stays open anyway,
[`clanka doctor end-session`](/cli/doctor/#end-session) closes it without
sleeping on it.

How long a conversation runs before the companion tires is its
[allowance](/conversations/sleep/#getting-tired).
`plugins.entries.clanka.settings.session_tokens` in the profile's
`config.yaml` sets it for this companion, over `[session] tokens` in
clanka's `config.toml`:

```yaml
plugins:
  entries:
    clanka:
      settings:
        session_tokens: 128000
```

## Let Nightshade write the soul

Nightshade is a Hermes agent that interviews you about the companion you
want, writes its `soul.md`, lints it and makes the profile.

```sh
clanka hermes nightshade --model claude-opus-5-5
hermes -p nightshade chat
```

Without `--model` it runs on the Hermes default. A stronger model interviews
better, and the session is short.

From a clone, `hermes/install.sh --source` builds the checkout and installs
that instead, to try a change before it is released. It needs what
[building from source](/getting-started/#build) needs, plus Python 3.11 or
newer.

## Update

```sh
clanka upgrade
```

[`clanka upgrade`](/cli/upgrade/) installs the latest release over the CLI,
the plugin and the skill, after the same checksum check. It ends with
`clanka hermes refresh`, which gives every profile clanka made the new
plugin and restarts the gateway.

<Aside type="caution">
  Where systemd runs the gateway, the restart interrupts live sessions without
  asking. Use `clanka upgrade --no-restart` to leave the gateway running the
  old build, and restart it yourself later.
</Aside>

## Gotchas

**Only the gateway restarts.** `clanka hermes refresh` and `clanka upgrade`
restart the Hermes gateway service. The Hermes desktop app, a terminal
`hermes -p nova chat`, and the background gateway that `hermes chat` starts
for itself (`hermes gateway run --idle-exit`) keep the plugin build they
loaded. Quit and reopen them after an upgrade.

**A changed persona.** Since 0.1.2, a companion that is already open takes up
a persona settled with `clanka soul continue` or `update` on its next turn.
With an older plugin, every turn says "the persona changed" until whatever
has the companion open restarts. Editing only the traits still needs that
restart.

**Photos need a model with vision.** A companion profile sends each photo to
the model as an image (`model.supports_vision`), never as a description, so a
model that can't take images can't see it. Profiles made before 0.1.3 get
the setting from `clanka hermes refresh`.

**Memory keeps what was said about a photo, not the photo.** The turn is
recorded as your words and `*shows you a photo*`. What the companion
remembers of the picture is what it said about it in its reply.
