clanka reads one optional file, `config.toml`. Every section in it is
optional, and an unknown section or key is an error.

## Files

On Linux:

| Path                             | What it holds                                     |
| -------------------------------- | ------------------------------------------------- |
| `~/.config/clanka/config.toml`   | The settings on this page.                        |
| `~/.config/clanka/souls/<id>.md` | Each companion's `soul.md`.                       |
| `~/.config/clanka/lore/`         | The [lore](/lore/reading/), unless `[lore] dir` says otherwise. |
| `~/.config/clanka/keys/<id>.key` | Database keys, only with `[keys] store = "file"`. |
| `~/.config/clanka/keys/diagnostics.token` | The [diagnostics upload token](/cli/diagnostics/#token), only with `[keys] store = "file"`. |
| `~/.local/share/clanka/`         | The databases, the embedding model and the [diagnostics log](/cli/diagnostics/#the-log). |

On macOS, config and data both live in
`~/Library/Application Support/clanka`.

## `[model]`

The model the companion talks and remembers with: any OpenAI-compatible chat
completions endpoint with tool calls. `clanka chat`, memory writing, sleep,
`clanka soul update`, `clanka soul draft` and `clanka doctor reinterpret`
need it.

```toml
[model]
base_url = "https://api.example.com/v1"
model = "some-model"
api_key_env = "CLANKA_MODEL_API_KEY"
```

### `base_url`

The endpoint, up to and including `/v1`. Required.

### `model`

The model's name as the endpoint knows it. Required.

### `api_key_env`

The environment variable that holds the API key. The key itself is never in
the file.

- Default: `CLANKA_MODEL_API_KEY`

### `effort`

How hard the model thinks before it answers: `none`, `minimal`, `low`,
`medium`, `high`, `xhigh` or `max`. It is sent as `reasoning_effort` with
every request, replies and memory writing alike. A model takes the levels it
knows, and an endpoint may refuse one it doesn't.

- Default: unset, which sends no effort and leaves it to the endpoint

## `[companions.<id>]`

What one companion sets instead of `[model]`'s. `<id>` is the `id` in its
`soul.md`, which is also the file's name.

```toml
[model]
base_url = "https://api.example.com/v1"
model = "some-model"
effort = "low"

# Another model on the same endpoint.
[companions.0198c1de-5f3a-7c41-9b1e-2f6a8d4e7c10]
model = "another-model"
effort = "high"

# An endpoint of its own.
[companions.0198c1de-6a02-7d55-8c3f-91b7e2a4d6f0]
base_url = "https://api.other.example/v1"
model = "their-model"
api_key_env = "OTHER_API_KEY"
```

Every key is optional, and a companion keeps `[model]`'s for the ones it
leaves out. An id that is no UUID is an error.

Without a `[model]` section, a companion needs a `base_url`, a `model` and an
`api_key_env` of its own, and a companion with no section has no model.

A companion on Hermes runs on its profile's model instead: see
[`clanka hermes profile`](/cli/hermes/#profile).

### `base_url`

An endpoint of this companion's own, up to and including `/v1`. It needs
`api_key_env` beside it, or the file is refused: `[model]`'s key is never
sent to another endpoint.

- Default: `[model]`'s `base_url`

### `model`

The model this companion talks and remembers with, as its endpoint knows it.

- Default: `[model]`'s `model`

### `api_key_env`

The environment variable that holds the key this companion's requests carry.

- Default: `[model]`'s `api_key_env`

### `effort`

How hard that model thinks, with the levels of [`[model]`'s `effort`](#effort).

- Default: `[model]`'s `effort`

## `[embedding]`

The local model that turns text into vectors for recall.

```toml
[embedding]
model = "multilingual"
duplicate_similarity = 0.9
```

### `model`

`english` is a small English model (about 23 MB). `multilingual` is for
companions that talk in other languages (about 250 MB, and slower per text).

- Default: `english`

A companion keeps the model its vectors were built with, and refuses to open
until they match. After changing this setting, run
[`clanka embedding`](/cli/embedding/), then
[`clanka doctor reembed`](/cli/doctor/#reembed) on each companion.

### `duplicate_similarity`

How alike a new memory and one already kept must be for the new one to be
refused as a copy. Above 0, at most 1.

- Default: `0.92`

Models spread similar texts differently, so it may need changing with the
model.

## `[recall]`

The ranking recall uses. Set any of the keys; the rest keep their defaults.
[Tuning recall](/memory/tuning-recall/) shows how to measure a change.

```toml
[recall]
limit = 6
min_relevance = 0.3
```

### `limit`

Most memories returned per turn.

- Default: `8`

### `seared_limit`

Most seared memories per turn, so the same moments do not come up forever.

- Default: `2`

### `min_relevance`

Below this relevance a memory is never recalled, seared or not.

- Default: `0.25`

### `min_score`

Below this final score a memory has faded out of reach.

- Default: `0.05`

### `fts_weight`

Added to the relevance for the best full-text match, and scaled down for
weaker matches. It lets the names and places in a memory's facts count.

- Default: `0.15`

### `mood_weight`

How strongly the companion's mood pulls same-feeling memories up and others
down.

- Default: `0.15`

### `thread_boost`

Multiplier for open threads that have not been resolved.

- Default: `1.2`

### `faint_half_life`

The number of newer memories after which a faint memory's rank halves.

- Default: `40`

### `normal_half_life`

The same for normal and vivid memories.

- Default: `400`

### `vivid_floor`

Vivid memories never sink below this factor, however old they are.

- Default: `0.35`

### `level_weights`

The weight per level, in the order faint, normal, vivid, seared.

- Default: `[0.8, 1.0, 1.15, 1.3]`

## `[session]`

The conversation's allowance, for every companion on this machine. See
[Getting tired](/conversations/sleep/#getting-tired).

```toml
[session]
tokens = 128000
```

### `tokens`

Estimated tokens of conversation (one per 3 characters) before the companion
tires; a dream ends when it fills them. Sleep and waking read this much of the
night. `--session-tokens` and a Hermes profile's `session_tokens` win over it
for one companion. A model with a window under 128,000 tokens, or a
conversation in Chinese or Japanese, needs less.

- Default: `64000`

## `[lore]`

Where the [lore](/lore/reading/) lives and how much of it a turn shows, for
every companion on this machine. Which entries each one reads is its
`soul.md`'s `lore` grants.

```toml
[lore]
dir = "/srv/worlds/ashford"
tokens = 6000
```

### `dir`

The lore directory. A relative path is relative to the config directory.

- Default: `lore/` beside `souls/` (`~/.config/clanka/lore`)

### `tokens`

Estimated tokens of lore a turn may show: the index and the open entries. It
is apart from the memory budget and the conversation's allowance, so lore
never tires a companion. It is the only limit on how many entries are open:
when it runs out, the one read longest ago closes until it is named again.
An entry whose text alone is longer doesn't open.

- Default: `3000`

## `[keys]`

Where a new companion's database key is put, and the
[diagnostics upload token](/cli/diagnostics/#token).

```toml
[keys]
store = "file"
```

### `store`

`secret-service` puts the key in the Secret Service (the login keychain on
macOS), under the service `clanka`. `file` puts it in
`~/.config/clanka/keys/<id>.key`, a file only you can read, for a machine
with no Secret Service. The upload token goes to the same place, as
`diagnostics-upload-token` or `keys/diagnostics.token`.

- Default: `secret-service`

<Aside type="caution">
  With `file`, whoever can read your files can read the database too: the key no
  longer waits on your login.
</Aside>

## `[ui]`

How clanka's output looks on a terminal.

```toml
[ui]
glyphs = "unicode"
```

### `glyphs`

Which symbols mark the lines clanka prints and its
[progress row](/cli/#progress).

- `nerd` uses Nerd Font symbols. In a font without them they show as boxes.
- `unicode` uses `✓`, `✗`, `!` and a braille spinner, which nearly every
  monospace font has.
- `auto` picks `nerd` when either of these holds, and `unicode` otherwise:
  - The terminal draws Nerd Font symbols itself, whatever font it is set to.
    clanka knows Ghostty, kitty, WezTerm and Rex by `TERM`, `TERM_PROGRAM`,
    `KITTY_WINDOW_ID` and `REX_SESSION`.
  - A font with `Nerd` in its file name is installed on this machine, in
    `~/Library/Fonts`, `/Library/Fonts`, `~/.local/share/fonts` or
    `/usr/share/fonts`. clanka skips this check over SSH, where the font that
    draws is on the other machine.

- Default: `auto`

No terminal reports its font, so `auto` is a guess. If you see boxes, set
`unicode`.

## `[diagnostics]`

The local log of what clanka does, which
[`clanka diagnostics`](/cli/diagnostics/) counts.

```toml
[diagnostics]
enabled = false
```

### `enabled`

Whether clanka writes the log. It holds numbers and fixed words, never what
was said or remembered, and it is never sent anywhere.
[What is kept](/cli/diagnostics/#what-is-kept) lists every event.

- Default: `true`

Turning it off stops new events, and stops the send at the end of a
conversation. The log already written stays until you delete it. Restart
anything that has a companion open for the change to reach it.

## `[diagnostics.upload]`

Where the diagnostics log is also sent. Without this section it never leaves
the machine. [`clanka diagnostics send`](/cli/diagnostics/#send) says what
is sent and when.

```toml
[diagnostics.upload]
url = "https://diagnostics.example.com/v1/events"
```

### `url`

The endpoint that takes the events: your own, or one someone you trust runs
for you. Required.

The token an endpoint asks for is not in this file.
[`clanka diagnostics token`](/cli/diagnostics/#token) makes it, or reads one
you were given, and puts it away with the database keys.

## Environment

### `NO_COLOR`

Set to anything but an empty value to turn colors off, as
[no-color.org](https://no-color.org) describes. The marks and the
[progress row](/cli/#progress) stay.

- Default: unset, which colors a stream that is a terminal

```sh
NO_COLOR=1 clanka soul lint ~/.config/clanka/souls/<id>.md
```

### `CLANKA_PROGRAM_STATUS`

Set to `0` to stop clanka from reporting
[program status](/cli/#program-status) to the terminal and setting the window
title. The [progress row](/cli/#progress) stays.

- Default: unset, which reports when stderr is a terminal

```sh
CLANKA_PROGRAM_STATUS=0 clanka chat ~/.config/clanka/souls/<id>.md
```
