---
title: web
description: Look through what your companions remember in a browser, on this machine or over your tailnet, and repair it there with --doctor.
---

```sh
clanka web [--port <port>] [--no-open] [--doctor] [--tailnet]
```

Serves a page from this machine and opens it in your browser. The page lists
the companions set up here, and for the one you pick it shows:

- **Overview:** its mood and why, the note it left itself for the next
  reply, the soul sections it wrote with their earlier versions, its open
  threads, and how many memories it holds of each type and level.
- **Memories:** every memory, with filters by type, level and status and a
  search box. Opening one shows its facts, the turns it was written from,
  its history (each rewrite, with how far a drift moved it) and what it
  replaced or was replaced by. A fact that was never said in those turns is
  marked, as [`clanka doctor check-facts`](/cli/doctor/#check-facts) lists
  it.
- **Recall:** what a query brings up, with the relevance and score behind
  the order, as [`clanka recall`](/cli/recall/) prints it. Nothing is marked
  as recalled.
- **Log:** every write to the memory, as
  [`clanka doctor log`](/cli/doctor/#log) prints it. The times are in UTC, in
  the form [`clanka doctor rollback --to`](/cli/doctor/#rollback) takes.
- **Doctor:** whether the companion is frozen and whether a conversation is
  open. With `--doctor`, the repairs below.

The search box finds words in a memory or its facts; `#12` finds the memory
with that number.

The button at the left of the header closes the list of companions, to give
the one you are reading the whole width, and opens it again. The browser
remembers which you left it as.

## It only reads, unless you ask

Without `--doctor` the page has nothing that changes a memory, and the
server answers nothing but reads. A frozen companion shows a banner that
says so, and the Doctor tab says how to turn the repairs on.

Opening a companion does what [`clanka memories`](/cli/memories/) does to
its database: one from an older release is moved to the current schema. A
companion that was never opened is listed and is not opened, so looking
creates no database.

What another process writes while the page is open shows after **Refresh**.

## Repairing from the page

`clanka web --doctor` adds the repairs of [`clanka doctor`](/cli/doctor/) to
the page. Each does what its command does and is written to the log the
same way.

| On the page                                   | Command                                                              | Needs the freeze |
| --------------------------------------------- | -------------------------------------------------------------------- | ---------------- |
| **Freeze**, **Unfreeze** in the Doctor tab    | [`freeze`](/cli/doctor/#freeze), [`unfreeze`](/cli/doctor/#unfreeze) | No               |
| **End the conversation** in the Doctor tab    | [`end-session`](/cli/doctor/#end-session)                            | No               |
| **Delete** on ticked memories, or an open one | [`delete`](/cli/doctor/#delete)                                      | No               |
| **Re-read** on ticked memories                | [`reinterpret`](/cli/doctor/#reinterpret)                            | Yes              |
| **Roll back** on a row of the Log             | [`rollback`](/cli/doctor/#rollback)                                  | Yes              |

The page never freezes on its own. A repair that needs the freeze is
disabled until you freeze, and the frozen banner stays, with an **Unfreeze**
button, until you unfreeze.

Every repair but a freeze asks first:

- **Delete** shows the memories, how many turns leave the transcript with
  them, and which memories become current again because what replaced them
  is going. If one of them is already gone, none is deleted.
- **Roll back** undoes the write you picked and every write after it. It
  shows which memories would be removed, restored and reopened, and the
  seared ones it leaves as they are, and runs once you type the companion's
  name. If the memory is written to between the question and your answer,
  nothing is rolled back and the page says to look again.
- **Re-read** lists the ticked memories it skips: seared ones, and ones
  that cite no turns. It needs the `[model]` in `config.toml`, with its API
  key in the environment `clanka web` was started in, and sends 20 memories
  to the model at a time.

There is no undo for a delete or a rollback, on the page or in the terminal.

Two commands are not on the page.
[`clanka doctor delete-all`](/cli/doctor/#delete-all) removes every memory,
the transcript and the sessions; the Doctor tab prints the command for the
companion you are reading instead of running it.
[`clanka doctor reembed`](/cli/doctor/#reembed) needs the server stopped.

## Who can read it, and repair

The server listens on `127.0.0.1` only and runs until Ctrl-C. With
[`--tailnet`](#over-your-tailnet) it also answers what Tailscale Serve sends
on from your tailnet. The address it prints ends in a token made for that
run:

```text
clanka web is at http://127.0.0.1:7333/#t=3fa9…
```

The page keeps the token for the tab and takes it out of the address bar.
Every request for a memory is refused without it, so another site open in
your browser cannot read your memories through the server. Anyone you give
the whole address to can, for as long as that run lasts. A new run makes a
new token, and a tab from the run before it stops working.

With `--doctor`, whoever has the address can also repair: delete memories
and roll the memory back. Run it for the repair and stop it after. The
server takes a change only from its own page: the browser names the page
each request comes from, and one from anywhere else is refused, token or
not.

The page loads nothing from outside the server and cannot be shown inside
another site's frame.

## Options

### `--port <port>`

The port on `127.0.0.1` to listen on. Default: `7333`.

### `--no-open`

Print the address without opening a browser.

### `--doctor`

Let the page repair the memory, not only read it. See
[Repairing from the page](#repairing-from-the-page).

### `--tailnet`

Answer through Tailscale Serve too, at the names it forwards to this port.
See [Over your tailnet](#over-your-tailnet).

## A companion on another machine

Run it there without a browser and forward the port over SSH:

```sh
ssh -L 7333:127.0.0.1:7333 other-machine clanka web --no-open
```

Then open the address it prints in a browser on this machine.

## Over your tailnet

To open the page from another device on your
[tailnet](https://tailscale.com/kb/1312/serve), such as your phone, have
Tailscale Serve forward a port to it once. `--bg` keeps the forward across
restarts:

```sh
tailscale serve --bg --https=7333 http://127.0.0.1:7333
```

Then start it with `--tailnet`:

```sh
clanka web --tailnet --no-open
```

It asks Tailscale which names Serve forwards to its port and prints an
address for each, with the same token:

```text
clanka web is at http://127.0.0.1:7333/#t=3fa9…
On your tailnet: https://my-machine.example.ts.net:7333/#t=3fa9…
```

Open that address on the other device. The server answers only at the
names Serve forwards to it, so another site cannot reach it under its own
name, and with `--doctor` it takes a change only from the page at that
address. Any device on your tailnet that Tailscale lets reach this machine
can use the address, for as long as the run lasts.

`--tailnet` refuses to start when Serve forwards nothing to the port, when
it forwards without HTTPS, and when Tailscale Funnel puts the forward on the
internet. Without `--tailnet` the server answers nothing that comes through
Serve, so a forward you leave in place exposes nothing between runs.
