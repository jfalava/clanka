```sh
clanka <command> [arguments]
```

Start with [`clanka init`](/cli/init/), edit the `soul.md` it prints, then
talk with the companion through [`clanka chat`](/cli/chat/) or serve it to an
MCP host with [`clanka mcp`](/cli/mcp/).

## The soul argument

Most commands take the companion's `soul.md` as their first argument: the
path that `clanka init` prints, and that [`clanka list`](/cli/list/) shows
again.

```sh
clanka memories ~/.config/clanka/souls/<id>.md
```

## Command reference

- **Set up:** [init](/cli/init/) creates a companion. [soul](/cli/soul/)
  lints, drafts and prints a soul, and settles a persona change.
  [embedding](/cli/embedding/) downloads the embedding model.
  [upgrade](/cli/upgrade/) installs the latest release.
- **Talk:** [chat](/cli/chat/) in the terminal. [mcp](/cli/mcp/) for an MCP
  host. [hermes](/cli/hermes/) for Hermes profiles and Nightshade.
- **Lore:** [lore](/cli/lore/) writes the world's lore and strikes what
  companions added that you don't want.
- **Inspect:** [memories](/cli/memories/) prints what a companion remembers.
  [recall](/cli/recall/) shows what one query brings up.
  [eval](/cli/eval/) measures recall over a cases file.
  [tics](/cli/tics/) finds prose tics in replies.
  [diagnostics](/cli/diagnostics/) counts how clanka has been running, from
  a local log that holds nothing that was said.
- **Repair:** [doctor](/cli/doctor/) freezes, logs, rolls back, rewrites and
  deletes memories.
- **Move:** [list](/cli/list/) shows the companions on this machine.
  [export](/cli/export/) and [import](/cli/import/) move one to another
  machine.
- **Test:** [debug](/cli/debug/) sends sample program status to the
  terminal and draws the progress row for it.

## Help

Every command explains itself, in three equivalent ways:

```sh
clanka help doctor rollback
clanka doctor rollback help
clanka doctor rollback --help
```

## Progress

On a terminal, a step that takes a while shows one live row on stderr. The
row has a spinner, the step's name, how far the step is and how long it has
taken. A second line carries detail when there is some, such as the model
call under way or why a request waits to be retried.

```text
⠹ Re-reading memories · 40/120 · 33% · 0:42
    model call 3
```

The row goes when the step ends. The lines clanka prints stay, above where
the row was. In `chat` the row runs from your message to the first words of
the reply.

With Nerd Font symbols the row starts with a timer symbol in place of the
spinner, and its detail line with a cog.
[`[ui] glyphs`](/configuration/#glyphs) says which symbols clanka uses.

clanka draws the row only when stderr is a terminal and `TERM` is not `dumb`.
Piped or redirected, it writes the same lines as before.
`CLANKA_PROGRAM_STATUS=0` does not turn the row off.

## Marks and colors

On a terminal, clanka marks three kinds of line. What a command did gets a
green `✓`. A warning gets a yellow mark and a failure a red one, each in place
of the `warning:`, `error:` or `Error:` the line starts with when piped.
`clanka: …` asides are dimmed, and help is colored.

```text
✓ Created Nova (01a1d14c-bd0a-7061-801f-f00fff263135).
✗ cannot read x.md: No such file or directory (os error 2)
```

`chat` sets `you>` in bold and the companion's name in cyan. `soul lint`
colors `warning:`, `ok` and `invalid`, and `eval` colors `ok`, `MISS` and
`NOISE`.

Each stream is judged alone. Stdout piped into a file or another command
gets plain lines even when stderr is a terminal, so scripts read what they
read before. [`NO_COLOR`](/configuration/#no_color) turns the colors off and
keeps the marks. The output of `--json`, `memories`, `recall`, `tics`,
`soul persona`, `soul guide` and `doctor log` is data and is never marked or
colored.

## Program status

On a terminal, the commands that take a while say what they are doing over
the [Program Status Protocol](https://www.superlogical.com/rex/docs/build/program-status)
(OSC 7501), and set the window title to match. Rex shows it on the tab and
in the session picker. A terminal that doesn't know the sequence ignores it.

| Command                                         | What it reports                                                       |
| ----------------------------------------------- | --------------------------------------------------------------------- |
| `chat`                                          | Replying, replied or no reply, and the reflections in the background. |
| `soul update`                                   | The share of memories re-read and the model calls made.               |
| `doctor reinterpret`                            | The model calls made.                                                 |
| `doctor reembed`                                | The share of memories embedded.                                       |
| `soul draft`                                    | The round.                                                            |
| `init`, `embedding`                             | The share of each model file downloaded.                              |
| `upgrade`                                       | The share of the release downloaded.                                  |
| `hermes profile`, `nightshade` and `refresh`    | The `hermes` call under way. `refresh` adds the share of profiles.    |

A run ends as `done` with one line of what it did, as `error` with the
reason, or as `idle` after Ctrl-C. A model request that waits to be retried
shows why.

Nothing is reported when stderr is not a terminal, when `TERM` is `dumb`, or
with [`CLANKA_PROGRAM_STATUS=0`](/configuration/#clanka_program_status).
`clanka mcp` never reports.

[`clanka debug status`](/cli/debug/) sends samples of these reports and draws
the progress row for them, to see how a terminal shows both without a
companion or a model.

## Global flags

### `--help`, `-h`

Print help for the selected command without running it. `-h` prints a
summary.

```sh
clanka chat --help
```

### `--version`, `-V`

Print the version.

```sh
clanka --version
```
