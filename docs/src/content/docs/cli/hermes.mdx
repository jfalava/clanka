---
title: hermes
description: Run companions on Hermes, with a profile per companion and Nightshade, the agent that interviews you and makes one.
---

```sh
clanka hermes <subcommand>
```

Needs the clanka plugin that `hermes/install.sh` installs under
`~/.hermes/plugins/clanka`, and `hermes` on your `PATH`. See the
[Hermes guide](/plugins/hermes/).

The commands drive the Hermes CLI and are safe to run again: they set the
same values and rewrite the profile's `SOUL.md`. They work the same from a
shell and from an agent's terminal inside Hermes.

## profile

```sh
clanka hermes profile [--provider <provider>] [--model <model>] [--effort <effort>] <profile> <soul>
```

Makes a Hermes profile that is one companion and nothing else:

- clanka's tools are the only toolset on every platform, listed directly
  instead of behind Hermes's tool-search bridge.
- Hermes's own memory, user profile, coding brief, toolchain probe and
  agent-style guidance are off.
- clanka may send messages (`allow_gateway_injection`), so
  [`/sleep`](/plugins/hermes/#saying-goodnight) can say goodnight for you.
- Photos go to the model as images (`model.supports_vision`), not as a note
  to look at them with a tool the profile doesn't have. Memory records each
  as `*shows you a photo*`. Give the companion a model that takes images.
- Memory and lore reach the model whole (`hooks.output_spill.enabled`
  false). Hermes otherwise cuts a hook's context over 10,000 characters to
  its first and last 500 and a file path.
- `SOUL.md` is the persona.

Each turn then carries the persona and the conversation instead of Hermes's
whole toolbox. On Haiku, the system prompt and tools went from about 19k
tokens on a stock profile to about 1.2k.

The root's own `providers:`, model aliases, reasoning overrides and
`model_overrides` are copied in. The keys those providers read are copied
from `~/.hermes/.env` into the profile's, since a profile loads only its own
`.env`.

Run it again after editing the persona to refresh `SOUL.md`. A toolset you
added next to clanka on a platform is kept. A gateway that already serves
the profile re-reads its config on its own.

### `<profile>`

The Hermes profile to make or refresh. Lower case, one word.

### `<soul>`

The companion's `soul.md`, as printed by `clanka init`.

```sh
clanka hermes profile nova ~/.config/clanka/souls/<id>.md
hermes -p nova chat
```

### `--model <model>`

The model this companion runs on, as its provider names it
(`model.default`). It writes the replies and the memory.

- Default: the model the profile has, which on a new profile is the root's

### `--provider <provider>`

The Hermes provider that model is asked at (`model.provider`), when it is not
the profile's: a built-in one such as `anthropic`, or one of the root's
`providers:`, which are copied in first.

- Default: the provider the profile has

Hermes drops a `model.base_url` the provider before left in the profile when
it knows whose it is. One it can't place, such as a proxy, stays, and the
command warns that the new provider's requests go there.

### `--effort <effort>`

How hard the model thinks, before a reply and when it writes memory: `none`,
`minimal`, `low`, `medium`, `high`, `xhigh` or `max`. A model takes the levels
it knows, and Hermes rounds the rest to one it does.

- Default: the effort the profile has

The flag sets two keys. `agent.reasoning_effort` is for the replies.
`auxiliary.clanka_memory.reasoning_effort` is for the memory: Hermes passes a
plugin's model call none of the profile's effort, so the plugin writes memory
through an auxiliary task of its own, `clanka_memory`, which follows the chat
model and has this one setting.

Without the flag, a memory task that has no effort takes the one the replies
have, so an `agent.reasoning_effort` you set by hand reaches the memory the
next time this command or [`clanka hermes refresh`](#refresh) runs. An effort
the task already has is kept, whatever the replies' is.

An effort set for that one model in `agent.reasoning_overrides` wins over the
flag for the replies, not for the memory, and the command warns when there is
one.

```sh
clanka hermes profile nova ~/.config/clanka/souls/<id>.md \
  --provider anthropic --model claude-haiku-5-5 --effort low
```

Without the flags the profile keeps what it has, so running the command
again, or [`clanka hermes refresh`](#refresh), never moves a companion to
another model or changes an effort it has.

## nightshade

```sh
clanka hermes nightshade [--profile <profile>] [--model <model>]
```

Makes the Nightshade profile: an agent that interviews you about the
companion you want, writes its `soul.md`, lints it and wires it in with
`clanka hermes profile`.

The terminal and file tools are all it has. The root's own `providers:`,
model aliases and their keys are shared with it, so `/model <alias>` works
in its chat.

### `--profile <profile>`

The Hermes profile to make or refresh.

- Default: `nightshade`

```sh
clanka hermes nightshade --profile soulwriter
```

### `--model <model>`

The model it runs on, as Hermes names it. A stronger model interviews
better, and the session is short.

- Default: the Hermes default

```sh
clanka hermes nightshade --model claude-opus-5-5
hermes -p nightshade chat
```

## refresh

```sh
clanka hermes refresh [--no-restart]
```

Brings every profile clanka made up to the installed plugin, then restarts
the gateway. `hermes/install.sh` and [`clanka upgrade`](/cli/upgrade/) run
it, because each profile runs a copy of the plugin and a running gateway
keeps the build it loaded.

- A profile with a soul in its clanka settings gets what
  `clanka hermes profile` does with that soul, on the model and the effort
  it has. If its replies have an effort and its memory task has none, the
  task gets the replies'.
- A profile whose `SOUL.md` is Nightshade's gets what
  `clanka hermes nightshade` does, on the model it has.
- Any other profile is left alone.

A profile that fails is named, the rest are still done, and the command
fails.

<Aside type="caution">
  Where systemd runs the `hermes-gateway` and `hermes-serve` units, the restart
  is `systemctl --user restart`, which interrupts live sessions without asking.
  Otherwise it is `hermes gateway restart`, which asks first.
</Aside>

### `--no-restart`

Leave the gateway running the build it loaded.

- Default: `false`

```sh
clanka hermes refresh --no-restart
```
